Leaderboards — one table per judge

Two judges score every diff, but their scales differ (fable-5 runs 1–2 points more generous than gpt-5.5-pro), so scores from different judges are never mixed into one ranking. Rows where the judge shares a model family with the candidate are flagged same-family — read those with self-preference in mind. Quality averages the completed runs; end-to-end counts every attempted task, scoring failures as 0 — the number that punishes a configuration for not finishing.

Objective gate — do the reference's held-out tests pass?

Three tasks carry runnable gates: the reference PR's own test files are applied over each candidate's diff and run in a no-network container. fix-tmux's gate is behavioral (it builds the gem and checks shipped scripts) — passing it means the change demonstrably works. The fix-review and daemon gates turned out to be interface-strict: they unit-test the reference's internal class names, and every candidate chose a different architecture, so a fail there means "diverged from the reference's internals", not "doesn't work". Read them as conformance data, not a ranking.
