A workflow turns one brief into a durable outcome

A Hive workflow is a reusable, ordered process. The workflow definition names the stages; each task run carries one brief through them. The result is agent work you can inspect, resume, and steer.

  1. Start with a brief

    Hive creates a task folder, preserving the request that entered this run.

  2. Produce one useful artifact

    An assigned agent or human reads the durable context and writes the stage's named output.

  3. Cross an explicit checkpoint

    A status marker tells Hive to advance, pause for a human, retry, or return the work for revision.

  4. Reach a defined outcome

    The daemon repeats that loop until the workflow's terminal stage says what “done” means.

Why not one giant prompt?

A single prompt keeps progress in a transient conversation. Hive records artifacts and transitions on disk, so an interruption does not erase the work and a person can review the exact handoff before autonomy continues.

  • Repeat the same team process without rebuilding the prompt.
  • Choose the right agent, model, and permissions for each stage.
  • See what happened, resume safely, and intervene at bounded checkpoints.

One engine, many processes

  • The flagship coding workflow: an idea becomes a reviewed pull request.
  • Editorial work: a brief becomes researched, approved, publish-ready copy.
  • Research or triage: evidence becomes a recorded recommendation or decision.
