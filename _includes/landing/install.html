Install & run your first task

Hive ships as the hive-cli rubygem attached to each GitHub Release, signed with cosign keyless attestation. Every channel verifies the signature before installing; native Hive web then authenticates its matching release bundle before extraction. Prerequisites: Ruby 3.4, git, an authenticated gh, and the agent CLIs you plan to use (claude, codex).

macOS (Homebrew)

brew install ivankuznetsov/hive/hive

Arch Linux (AUR)

yay -S hive-bin

Linux (glibc x86_64 / aarch64)

tmpdir="$(mktemp -d)" && trap 'rm -rf "$tmpdir"' EXIT \
  && curl -fsSL https://raw.githubusercontent.com/ivankuznetsov/hive/v{{ site.hive_version }}/install.sh \
       -o "$tmpdir/hive-install.sh" \
  && bash "$tmpdir/hive-install.sh"

Then set up Hive in your project

cd ~/Dev/your-project
hive setup           # initialize the project and start native Hive web
# open the reported URL (normally http://127.0.0.1:4567)

On Linux and macOS, hive setup installs, enables, starts, and probes the per-user daemon and Hive web services. It reports the effective URL and keeps installed, enabled, running, and ready state distinct. The untouched setup is loopback-only: it never creates LAN/public binding or Tailscale exposure.

Choose a different operating mode

hive setup --no-service     # no web-service mutation; use foreground mode
hive web                    # blocking foreground server
hive setup --no-bootstrap   # diagnose only; provision nothing
hive tui                    # power-user terminal dashboard

On Windows, use WSL with systemd for native Hive web, or Hivebox through Docker Desktop. Choose Hivebox for container isolation, multiple local instances, containment of untrusted agents, or a reproducible server/NAS deployment.
